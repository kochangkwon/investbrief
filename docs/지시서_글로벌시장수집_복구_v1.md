## 0. 배경 — 실측 근거 (재조사 불필요)

브리프 110건 전수 + 라이브러리 상태 조사 결과:

| 사실 | 근거 |
|---|---|
| global_market 수집 실패가 **만성적** | 110건 중 **71건(65%)이 0개**. 월별 성공률 3월 40% → 4월 21% → 5월 21% → 6월 45% → 7월 26% → 8월 35% |
| 최근 패턴 | 8/10~14 n=0 → 8/17~ n=3(전부 Finnhub 프록시) → 8/21만 n=10 → 8/24~25 다시 n=3 |
| yfinance가 **구버전 고정** | `requirements.txt`에 `yfinance==0.2.55`(2025-04 릴리스). 현행 최신 **1.6.0** — 메이저 버전 점프 |
| 차단 메커니즘 추정 | `.venv`에 **curl_cffi 미설치(0개)** 확인. 0.2.55는 평범한 `requests` 사용 → Yahoo 봇탐지에 취약. 최신 yfinance는 curl_cffi 브라우저 임퍼소네이션으로 우회. 간헐 성공(8/21)은 rate limit 특유 패턴 |
| Finnhub 폴백의 한계 | 무료 플랜은 **ETF quote만** 지원(`fetcher_finnhub.py` 문서에 "❌ 매크로/선물 — 무료 plan 미지원" 명시). 그래서 SPY/QQQ/DIA 3종이 최대치이고 **VIX·환율은 원천적으로 폴백 불가** |
| ⚠️ **FDR은 독립 폴백이 아님** | 실측 확인: FDR로 `VIX`/`USD/KRW`/`US500`/`N225` 조회 시 전부 **`query2.finance.yahoo.com`** 백엔드 호출. yfinance가 막히는 상황에서 FDR도 같이 죽을 가능성이 높음. **(단, 국내 지수는 KRX/네이버를 쓰므로 정상 — 혼동 주의)** |
| 판정불가 발생 경로 | 위험진단 3축 중 VIX·환율이 `global_market` 의존 → 2축 결손. 외인 축은 KRX 정상이나 연속 순매도 2일(8/24 −4,589, 8/25 −34,391, 그 전 8/21 +15,887)로 임계 3일 미달 → score 0 → **2축 결손 + 무시그널 = 판정불가** (F3 설계대로 동작) |

**핵심 판단:** "판정불가"는 회귀가 아니라 **기존 결함의 가시화**다. 이전에는 같은 상황에서 "🟢 정상"으로 오보했다. 따라서 이 지시서의 목적은 경보를 끄는 것이 아니라 **데이터를 실제로 복구**하는 것이다.

## P1 — yfinance 업그레이드 (근본 해결, 단 외부 의존)

### P1-1. 버전 상향 및 호환성 점검

**변경:**
1. `backend/requirements.txt`: `yfinance==0.2.55` → 최신 안정 버전으로 상향(설치 시점 최신 확인 후 **정확한 버전으로 재고정**. 무고정 금지 — 재발 방지).
2. 설치: `cd backend && .venv/bin/pip install -U yfinance` 후 `.venv/bin/pip show yfinance curl_cffi`로 **curl_cffi 동반 설치 확인**(이게 차단 우회의 핵심).

**호환성 점검 (0.2.x → 1.x는 breaking change 가능):**
현재 호출부는 `app/collectors/market_collector.py`의 `_download()` 한 곳:
```python
yf.download(symbols, period="2d", group_by="ticker", progress=False, threads=threads)
```
그리고 결과를 `df[ticker]["Close"]`로 접근한다. 아래를 반드시 확인:
- `auto_adjust` 기본값이 True로 바뀌었는지 → 지수/환율은 배당조정 무관하나, **컬럼 구성이 달라지면** `Close` 접근이 깨질 수 있음.
- `group_by="ticker"` 시 멀티인덱스 구조 유지 여부(`multi_level_index` 인자 신설 여부 포함).
- 단일 심볼일 때의 분기(`len(symbols)==1`) 동작.

**검증 스크립트 (로컬에서 직접 실행 — 클라우드는 Yahoo 차단이라 검증 불가):**
```bash
cd backend && .venv/bin/python -c "
import yfinance as yf, warnings; warnings.filterwarnings('ignore')
from app.collectors.market_collector import TICKERS
symbols=list(TICKERS.values())
df=yf.download(symbols, period='2d', group_by='ticker', progress=False, threads=True)
print('empty?', df is None or df.empty)
for k,t in TICKERS.items():
    try: print(f'  {k:8s} {t:10s} rows={len(df[t][\"Close\"].dropna())}')
    except Exception as e: print(f'  {k:8s} {t:10s} ERR {type(e).__name__}')
"
```

**완료 기준:** 위 스크립트에서 **10/10 종목 rows≥1**. 실패 종목이 있으면 그 티커만 P2 폴백 대상으로 넘긴다.

**롤백:** 업그레이드 후 다른 모듈(`us_market/fetcher.py`도 yfinance 사용)에서 회귀가 나면 `requirements.txt`를 되돌리고 P2만 진행. **P2가 본 지시서의 필수 항목이다.**

## P2 — 네이버 독립 폴백으로 VIX·환율 복구 (필수)

### 왜 네이버인가
Finnhub(무료)는 ETF만, FDR 해외지표는 Yahoo 의존(위 §0 실측). **현재 확실히 살아있는 유일한 독립 소스는 네이버**다 — 뉴스·국내지수·시총 수집이 전부 정상 동작 중이고, `price_collector._fetch_naver_index_history()`라는 **검증된 구현이 이미 존재**한다(KRX 지수 차단 대응으로 만든 것).

### P2-1. 네이버 심볼 코드 확정 (구현 전 필수 선행)

클라우드 환경에서는 네이버가 차단되어 심볼을 실측 확정하지 못했다. **구현 착수 전 로컬에서 아래를 실행해 실제 응답 스키마와 코드값을 확정하고, 결과를 이 지시서 하단 "확정 심볼" 절에 기록**할 것.

```bash
cd backend && .venv/bin/python -c "
import httpx, json
H={'User-Agent':'Mozilla/5.0'}
cands = {
 '해외지수 VIX':   'https://api.stock.naver.com/index/.VIX/price?pageSize=3&page=1',
 '해외지수 SPX':   'https://api.stock.naver.com/index/.INX/price?pageSize=3&page=1',
 '환율 USDKRW':    'https://api.stock.naver.com/marketindex/exchange/FX_USDKRW/prices?page=1&pageSize=3',
 '환율(대체경로)': 'https://m.stock.naver.com/front-api/marketIndex/prices?category=exchange&reutersCode=FX_USDKRW&page=1&pageSize=3',
}
for name,url in cands.items():
    try:
        r=httpx.get(url, headers=H, timeout=10)
        print(f'== {name}: HTTP {r.status_code}')
        print('   ', r.text[:300])
    except Exception as e:
        print(f'== {name}: {type(e).__name__} {e}')
"
```
- 위 후보 URL이 전부 404/스키마 불일치면, 브라우저에서 `m.stock.naver.com` 해외증시·시장지표 페이지의 **네트워크 탭에서 실제 XHR 엔드포인트를 확인**해 대체한다.
- 최소 목표는 **VIX와 USD/KRW 2종**이다(위험진단 2축). 지수 3종은 이미 Finnhub 프록시가 커버하므로 후순위.

### P2-2. 폴백 구현

**파일:** `app/collectors/price_collector.py` (네이버 호출 캡슐화 위치 — 기존 `_fetch_naver_index_history` 옆)

1. `fetch_naver_global_quote(kind: str) -> Optional[dict]` 신규:
   - `kind`는 `"vix"` / `"usdkrw"` 등 내부 키. P2-1에서 확정한 URL·스키마로 최근 2개 종가를 받아 `{"close": float, "change": float, "change_pct": float}` 반환.
   - 실패·스키마 불일치 → `None` + `logger.warning`. **절대 0.0으로 채우지 말 것**(F1에서 고친 것과 같은 실수 반복 금지).
   - 기존 `_NAVER_MCAP_HEADERS` 재사용, timeout 8초.

**파일:** `app/collectors/market_collector.py`

2. `_apply_finnhub_proxies()` 뒤에 `_apply_naver_fallbacks(result)` 추가 — 이름은 `_apply_independent_fallbacks`로 통합해도 무방:
   - `result`에 `vix`/`usdkrw` 키가 없을 때만 채운다.
   - `label`에 출처를 명시한다(프록시 규칙과 동일): 예 `"VIX (네이버)"`, `"원/달러 (네이버)"`. **AI·독자가 소스를 구분할 수 있어야 한다.**
   - `asyncio.to_thread`로 감싼다(httpx 동기 호출 시).
3. `get_global_summary()` 말미의 폴백 호출 순서: **yfinance 결과 → Finnhub 프록시 → 네이버 폴백**. 부분 성공(예: yfinance가 8종만 성공)일 때도 **빠진 vix/usdkrw만 채우도록** 조건을 `if not result`가 아니라 **키 단위 결손 검사**로 바꾼다.
   > 현재 `_apply_finnhub_proxies`는 `if not result`(전멸)일 때만 호출되어, 부분 성공 시 결손 축을 못 메운다. 이 조건도 함께 수정할 것.

**완료 기준:**
- yfinance를 강제 실패시킨 상태에서 `get_global_summary()`가 **vix·usdkrw를 포함해 5종 이상** 반환.
- 그 결과로 `market_risk_simple.diagnose_simple()`이 **"판정불가"가 아닌 정상 등급**을 산출.
- 강제 실패 테스트 예시(`tests/test_global_fallback.py` 신규):
  ```python
  # yf.download를 monkeypatch로 예외 발생시키고, 폴백 경로만 검증
  # 네트워크 의존 테스트는 skip 처리하고, 병합 로직(키 단위 결손 채움)을 순수 함수로 분리해 검증
  ```
  → **네트워크 호출은 테스트에서 제외**하고, 병합·라벨링 로직을 순수 함수로 분리해 단위 테스트할 것.

## P3 — 경보 임계값 재설계 (P1·P2 완료 후)

**문제:** 현재 `scheduler._alert_global_market_failure()`는 `n < 5`면 "부분 실패" 경보를 보낸다. yfinance 실패가 상시화된 지금은 **매일 발동 → 알림 피로**로 경보가 무시된다.

**변경:** 개수 기준을 **"위험진단 필수 축 확보 여부"** 기준으로 바꾼다.
```python
# 의미 기반 판정 (개수가 아니라 '진단 가능한가')
essential = {"vix", "usdkrw"}
missing_essential = essential - set(global_market or {})
```
- `n == 0` → 🛑 전멸 (현행 유지)
- `missing_essential` 존재 → ⚠️ "위험진단 축 결손: VIX/환율 — 판정불가 상태" (하루 1회)
- 그 외 개수 부족(예: 유가·금 누락)은 **경보 없이 로그만** — 브리프 품질에 치명적이지 않음.

**완료 기준:** P1·P2 정상 동작 시 평상시 경보 0건. VIX/환율이 실제로 빠질 때만 발동.
