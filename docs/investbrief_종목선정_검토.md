## 2. 검증(feature_validation) 통계 설계 결함

이 부분은 아직 실행되지 않았습니다 (`FEATURE_VALIDATION_TARGET = 2026-09-11`, `.picker_signals.json` 미존재 확인). 즉 **지금 고칠 수 있습니다.**

### 🔴 2-1. 같은 데이터로 피처를 고르고 가중치까지 정함 (in-sample 데이터 스누핑)

```python
if f["diff_10d"] >= PICKER_MIN_DIFF and f.get("consistent") is True:
    signals.append({"feature": f["feature"], "weight": f["diff_10d"]})
```

9개 피처를 전수 테스트 → 가장 좋아 보이는 것을 채택 → **그 diff를 그대로 가중치로 사용**. 통계 검정 없음, 다중비교 보정 없음, 홀드아웃 없음. 코드 주석도 *"홀드아웃 미검증"*이라고 인정합니다.

무작위 노이즈 9개를 넣어도 |diff| ≥ 2%p인 게 1~2개는 나옵니다.

### 🔴 2-2. "robust" 판정이 독립 검증이 아님

`consistent = D+5 diff와 D+10 diff의 부호 일치`.
그런데 **D+5 구간은 D+10 구간에 포함**됩니다. 두 수익률의 상관은 구조적으로 0.7 이상이라 부호 일치는 거의 자동입니다. 필터로서 사실상 아무 일도 하지 않습니다.

**권고:** 비중첩 구간(D0~D5 vs D5~D10) 비교, 또는 시점 분할(전반부 학습 / 후반부 검증).

### 🔴 2-3. `MIN_SAMPLES = 200`이 실제 독립 표본 수를 크게 과대평가

- 하루 약 6건 × 34일 = 214건 (현재)
- 그런데 **D+10 윈도우가 10일씩 겹침** + **같은 날·같은 테마 종목은 강하게 교차상관**
- 동일 종목 반복: 삼성전자 6회, 009150 6회, SK하이닉스 5회, 068270 4회
- 실제 독립 관측치는 **알림일 수(≈34)** 에 가깝지, 200이 아닙니다

200건이 모여도 t-통계량은 부풀려집니다. 200건은 "34일치를 6번 센 것"입니다.

### 🟠 2-4. `institution_net` / `foreign_net`은 영구 NULL — 수급이 선정에도 검증에도 안 들어감

`NUMERIC_FEATURES`에 들어 있지만 **214건 중 0건 수집**됐습니다.

원인: `get_institution_foreign()`이 쓰는 **ka10009는 장중 미정산 시 공란**인데 스캔이 08:10에 돕니다. 정작 일자별 히스토리를 주는 **`get_investor_history()` (ka10059)는 수동 백테스트 스크립트(`scripts/backtest_accumulation.py`)에서만 쓰이고, 운영 파이프라인(선정·검증)에서는 호출되지 않습니다.**

즉 "기관·외국인 수급"은 문서상 선정 기준이지만 실제로는 **한 번도 반영된 적이 없습니다.**

### 🟠 2-5. `market_cap`이 신호 후보에 포함되어 있음

### 🟠 2-7. 프리필터와 픽커의 방향이 서로 충돌함

- **프리필터**: RSI·MA 이격·5일 수익률이 **높으면 제외** (과열 방어)

즉 픽커는 구조적으로 **"컷라인에 가장 가까운 과열 종목"** 을 고르게 됩니다.

실제로 스냅샷과 D+30 초과수익을 조인해 검증 로직을 미리 돌려봤습니다 (n=73, 6/29~7/14 — **국면이 하나뿐이라 참고용**):
