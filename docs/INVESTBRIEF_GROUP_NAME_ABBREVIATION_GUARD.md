# 지시서 — 그룹명 줄임 표기 오태깅 가드 (2026-09-01 효성 실사고)

**목적**: 헤드라인이 계열사명을 그룹명으로 줄여 쓸 때("효성중공업" → "효성")
그룹명 가드가 뚫려 **지주사가 계열사 테마의 수혜주로 등록되는** 경로를 추출 단계에서 차단한다.

**우선순위**: P1 — 실매수 직전 사고 2회차 (2026-08-26 대상, 2026-09-01 효성).
효성은 B등급 자동매매 ON까지 등록됐다 (StockAI buy_alert id=94).

**작성 근거**: `theme_detection`·`theme_scan_results` 실측,
기사 원문 확인 (g-enews 2026-08-31), `theme_radar_service.py`, `stock_name_rules.py`

## 0. 실측

### 0-1. 사고 경로 (2026-09-01)

헤드라인 *"美 전력망 '현지생산' 승부…HD현대·효성 한발 앞서"* (키워드 "전력기기").
기사 본문의 주체는 HD현대일렉트릭·**효성중공업**(멤피스 765kV 변압기, 7,870억 계약)·LS일렉트릭.
**지주회사 ㈜효성(004800)은 본문에 등장하지 않는다.** 그러나:

1. 헤드라인이 처음부터 "효성"으로 줄여 써서, `_group_prefix_is_noise`가 찾는
   더 긴 계열사 토큰("효성중공업")이 텍스트에 없음 → 그룹명 가드 통과
2. Claude 검증("지주사면 NO" 조건 포함)도 이 헤드라인엔 YES 오판
3. → 전력 인프라 테마 수혜주로 등록 → StockAI B등급 자동매매 ON

### 0-2. 같은 종목, 같은 경로의 전례

- 효성 detection 6건 중 YES는 이번 1건뿐. 나머지는 전부 "효성重" 표기
  계열사 기사(NO 4, 실패 1) — **효성 단독 토큰은 사실상 항상 계열사 기사의 조각**이다.
- 2026-05-26 효성 매수(218,000×9, v3) → 06-26 청산 **−25.2% (−495,000원)**.
  당시 5월 말 스캔에도 효성이 "전력기기/초고압변압기" 키워드로 태깅돼 있어
  같은 오태깅 경로였을 가능성이 높다.

### 0-3. 그룹명 단독 토큰의 검증 통과율 (누적 실측)

| 이름 | 검증 결과 | 비고 |
|---|---|---|
| SK | NO 14 | "삼성·SK", "최태원 SK 회장" 등 |
| LG | NO 12 | "삼성·LG", "두산·LG·롯데" 등 |
| 한화 | NO 8 | ㈜한화는 사업회사이기도 함 |
| 두산 | NO 6 | |
| 효성 | **YES 1** / NO 4 | ← 이번 사고 |
| 신세계 | YES 1 / NO 2 | YES는 "신세계, 3분기…" — 주어+쉼표 정상 기사 |

그룹명 단독 토큰은 거의 전부 NO로 끝나며 검증 API 호출만 태운다.
그리고 헤드라인 하나가 새면 이번처럼 실매수까지 간다 —
**"Claude 검증에 위임"은 이 이름들에겐 대상(對象) 때와 같은 도박이다.**

## 1. 조치 — 회사 문맥 증거 요구를 그룹명 전체로 확장

2026-08-26 대상 사고 때 만든 `ambiguous_name_lacks_company_context`
(① 회사 접미 "그룹/홀딩스/㈜/(주)" 결합, ② 주어 위치 + 쉼표)를
`GROUP_PREFIX_NAMES` 전체에 적용한다. 신규 함수 없음 — 기존 검사 재사용.

`theme_radar_service.py` 추출 루프, 기존 일반명사 가드 조건 확장:

```python
# 기존: if (candidate in AMBIGUOUS_COMMON_NOUN_NAMES and ...)
if ((candidate in AMBIGUOUS_COMMON_NOUN_NAMES
        or candidate in GROUP_PREFIX_NAMES)
        and ambiguous_name_lacks_company_context(candidate, combined_text)):
    continue
```

`_group_prefix_is_noise`(계열사 동반 시 차단)는 그대로 둔다 —
선행 필터로 여전히 유효하며, 이 지시서는 그 **뒤의 구멍**(계열사명이
줄임 표기로만 존재)을 막는다.

### 실측 헤드라인 대입 검증

| 헤드라인 | 판정 | 근거 |
|---|---|---|
| "HD현대·효성 한발 앞서" (사고) | **차단** | 접미·쉼표 모두 없음 |
| "삼성·LG·효성 창업주 발자취…" | 차단 | 〃 (검증 호출 3건 절약) |
| "코스피 … 효성重 등" | 차단 | 〃 |
| "신세계, 3분기 실적 더 좋아진다" (정상 YES) | 통과 | 주어+쉼표 |
| "한화, LNG 글로벌 사업법인 설립" | 통과 | 주어+쉼표 (㈜한화 자체 사업) |
| "효성그룹 지배구조 개편" | 통과 | 그룹 접미 |

### 트레이드오프 (대상 때와 동일한 원칙)

쉼표 없는 정상 기사("농심 신라면 수출 확대")는 미탐된다.
미탐은 다음 스캔·다른 기사(대개 주어+쉼표 관례를 따름)로 복구되지만,
오탐은 실매수로 이어진다. 엄격한 쪽을 택한다.

**부수 수정**: 주어+쉼표 판정의 경계 문자에 말줄임표(…/⋯/...)·마침표를 추가했다.
실측 정상 YES 기사 *"면세점까지 흑자 전환…신세계, 3분기 실적 더 좋아진다"*가
기존 경계 집합(공백·괄호·따옴표)으로는 미탐됐기 때문 — 헤드라인 관례상
말줄임 뒤에 주어가 자주 온다. 기존 대상(對象)·동원 차단 케이스는 전부 무영향
(말줄임 뒤 + 쉼표 결합이어야만 통과가 넓어진다).

`theme_discovery_service.py`는 무변경 — 이미 그룹명을 전면 차단한다.
