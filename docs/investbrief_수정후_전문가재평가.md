## 4. 첫 2주 모니터링 체크리스트 (분석가 권장)

1. **알림 건수 추이** — 화이트리스트+display=30으로 후보가 얼마나 늘었나 (일 5~7건 → ?건). 급증 시 MAX_CANDIDATES·strict 재조정.
2. **prefilter reject 분포** — F5(재무리스크)와 F1-4 fail-closed가 각각 몇 건 걸러내는지. F5가 0건이면 배선 확인.
3. **미판정 건수** — 스캔 완료 메시지의 "검증 실패 N건". 지속 발생 시 API 한도/타임아웃 조정.
4. **지주사 재유입** — 한화·효성·두산·SK 단독 감지가 다시 나오는지 (나오면 v2 프롬프트가 못 거른 것 — GROUP 조건 재강화 필요).
5. **verdict 플립율** — 이제 NO가 기록되므로 같은 종목 NO→YES 전환 빈도 측정 가능. 플립율이 높으면 판정 자체가 불안정하다는 신호.
6. **스캔 소요시간** — 기존 6.6~11.9분에서 얼마나 늘었나 (F5+display 30 영향). 20분 초과 시 F5 캐시/동시성 조정.
7. **9월 말 검증 리포트** — 고유 60일 게이트 때문에 신호 채택은 9/11이 아니라 9월 말~10월 초. "표본 부족 대기" 메시지는 정상. train/val 양쪽 수치를 반드시 눈으로 확인 후 신호 채택 여부 판단.

## 5. 종합 판정

**"로직 결함이 해결됐는가?"** — 지적한 결함 중 구현 범위(긴급 4 + 검증 설계 6 + 스캔 4)는 코드·테스트·DB 리허설로 해결 확인됐습니다. 특히 좌측 꼬리(유상증자·재무위험·무필터 신규상장·과열 추격)를 자르는 방어와, 9월 검증이 노이즈를 신호로 채택하는 것을 막는 통계 장치는 실질적으로 강해졌습니다.

**"이제 돈을 벌어주는 시스템인가?"** — 별개의 질문이고, 아직 아닙니다. 이 시스템의 구조(공개 뉴스 D+1 스캔)에는 정보 우위가 없으므로, 기대할 수 있는 최선은 "나쁜 후보를 걸러 시장 대비 덜 잃거나 소폭 이기는 것"입니다. v1 실측 알파가 −19%p였고, v2 이후의 +15.5%p는 단일 국면 10일치라 증거가 아닙니다. **판단 유보 기간: 최소 9월 말 검증 리포트 + 상승·하락 2개 국면 데이터 확보 시점까지.** 그때까지는 알림을 매수 신호가 아닌 "검토 후보 리스트"로만 쓰는 현재 운영 방침이 옳습니다.
