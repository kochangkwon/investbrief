# 지시서: InvestBrief 재무 리스크 필터 (Financial Risk Flags) 구현

## 0. 작성 원칙 (이 지시서의 전제)

이 지시서는 다음 원칙으로 작성되었다. 구현 시에도 동일 원칙을 따른다.

1. **임의 판단 금지**: 모든 수치는 DART 공시 재무데이터에서 계산한다. 추정·보간·가정으로 값을 만들어내지 않는다. 데이터가 없으면 `null` + `"데이터 없음"` 사유를 출력한다.
2. **검증 우선**: API 필드명·계정과목명은 이 지시서의 예시를 그대로 믿지 말고, **실제 API 응답을 먼저 호출해서 확인한 후** 코드에 반영한다. (지시서 작성 시점의 지식이 최신 API 스펙과 다를 수 있음)
3. **임계값은 코드에 하드코딩 금지**: 판정 기준(주의/위험 임계값)은 전부 설정 파일로 분리한다. 아래 제시된 기본값은 일반적 재무분석 관행 기준이며 **절대적 기준이 아니다**. 사용자가 설정 파일에서 조정한다.
4. **판정 문구 제한**: 출력은 "플래그 + 근거 수치"만 표시한다. "이 종목은 나쁘다/좋다" 같은 정성 평가 문구를 생성하지 않는다.
5. **표준 규칙 준수**: 사용자가 제공한 실측값이 코드가 가져온 값과 다르면 사용자 제공값을 우선한다. Python 실행은 `python3`/`pip3`.

---

## 1. 목적

DART 공시 재무제표 데이터를 기반으로, 종목별 재무 리스크를 4개 지표군으로 정량 계산하여 InvestBrief에 "재무 리스크 플래그" 기능을 추가한다.

**이 필터는 매수 추천 도구가 아니라 네거티브 스크리닝(회피 신호) 도구다.**

## 2. 적용 범위

- **InvestBrief** (포트 8001): 종목 점검 API + 모닝브리프에 리스크 플래그 섹션 추가
- **StockAI 연동은 이번 범위에서 제외** (별도 지시서로 진행. 이번 구현에서는 InvestBrief 내 완결)

## 3. 데이터 소스

### 3.1 DART Open API (유일한 재무데이터 소스)

| 용도 | 엔드포인트 (검증 필요) | 비고 |
|---|---|---|
| 기업 고유번호 매핑 | `corpCode.xml` | 종목코드 → corp_code 변환. 로컬 캐시 |
| 전체 재무제표 | `fnlttSinglAcntAll.json` | 재무상태표/손익계산서/현금흐름표 계정 전체 |
| 공시 검색 | `list.json` | 유상증자 등 주요사항보고 감지 |
| 유상증자 결정 상세 | `piicDecsn.json` | 신주 수량·조달 목적별 금액 |

**구현 첫 단계에서 반드시 수행**: 위 4개 엔드포인트를 테스트 종목(예: 에코프로비엠 247540)으로 실제 호출하여 응답 JSON 구조를 파일로 저장하고, 실제 필드명·계정과목명(`account_nm`, `account_id` 등)을 확인한 뒤 파싱 코드를 작성한다. 이 지시서에 적힌 필드명과 실제 응답이 다르면 **실제 응답이 정답이다**.

- `reprt_code`: 11011(사업보고서), 11012(반기), 11013(1분기), 11014(3분기)
- `fs_div`: CFS(연결) 우선, 연결 없으면 OFS(별도)로 폴백하고 출력에 어느 쪽인지 명시
- API 키는 `.env`의 기존 DART 키 재사용. 코드에 하드코딩 금지

### 3.2 사용 금지

- Google Finance 사용 금지 (기존 규칙)
- 재무 수치를 웹 크롤링(네이버 증권 등)으로 가져오지 않는다. 재무데이터는 DART만 사용 (크롤링 값은 검증 불가·구조 변경 리스크)

## 4. 지표 정의 (계산식 — 정확히 이대로 계산)

모든 지표는 최근 3개 사업연도 + 최근 분기 기준으로 계산한다. 계정과목이 응답에 없으면 해당 지표는 `null` 처리하고 사유를 기록한다.

### 지표군 A: 감가상각 절벽 (건설중인자산)

```
A1. cip_ratio = 건설중인자산 / 유형자산 총액
A2. cip_yoy   = (당기 건설중인자산 - 전기 건설중인자산) / 전기 건설중인자산
```

- `건설중인자산` 계정이 `fnlttSinglAcntAll` 응답에 별도 계정으로 존재하는지 **먼저 실제 응답으로 확인**한다. 존재하지 않는 기업(주석에만 기재)은 A지표를 `null` 처리한다. 주석 파싱으로 대체하지 않는다(이번 범위 제외).

### 지표군 B: 이익-현금 괴리

```
B1. ocf_gap    = 영업활동현금흐름 - 영업이익
B2. capex_ratio = CAPEX / 영업활동현금흐름
   (CAPEX = 현금흐름표의 유형자산의 취득 + 무형자산의 취득, 실제 계정명 확인 후 반영)
B3. capex_초과연수 = 최근 3개년 중 CAPEX > 영업활동현금흐름 인 연도 수
```

- 영업활동현금흐름이 0 이하인 경우 B2는 계산하지 않고 `null` + `"OCF<=0"` 기록 (음수 분모로 비율 왜곡 방지)

### 지표군 C: 차입 리스크 (상대 지표)

```
C1. net_debt        = 이자발생부채 - 현금및현금성자산
   (이자발생부채 = 단기차입금 + 유동성장기부채 + 장기차입금 + 사채 + 리스부채.
    실제 응답의 계정 구성을 확인하고, 포함한 계정 목록을 출력에 명시)
C2. ebitda          = 영업이익 + 감가상각비 + 무형자산상각비
   (감가상각비·무형자산상각비는 현금흐름표 계정에서 취득. 없으면 ebitda = null)
C3. net_debt_to_ebitda = net_debt / ebitda   (ebitda <= 0 이면 null + "EBITDA<=0")
C4. interest_coverage  = 영업이익 / 이자비용  (이자비용 <= 0 이면 null)
C5. debt_growth     = (당기 이자발생부채 - 전기 이자발생부채) / 전기 이자발생부채
```

### 지표군 D: 희석 리스크 (유상증자)

`list.json`으로 최근 24개월 내 "유상증자결정" 공시를 검색하고, 존재하면 `piicDecsn.json`으로 상세 취득:

```
D1. dilution_ratio = 신주 발행 수 / 발행 전 총 주식수
D2. purpose_breakdown = 조달 목적별 금액 {시설자금, 운영자금, 채무상환자금, 타법인증권취득자금, 기타}
D3. non_growth_ratio = (운영자금 + 채무상환자금) / 총 조달금액
```

- D2의 목적 분류는 API 응답의 목적별 금액 필드를 그대로 사용한다. 응답에 목적별 구분이 없으면 D2, D3는 `null` 처리한다. **공시 본문 텍스트를 해석해서 목적을 추론하지 않는다.**

## 5. 판정 로직

### 5.1 설정 파일 (`risk_thresholds.json` — 예시)

```json
{
  "_comment": "기본값은 일반적 재무분석 관행 기준. 절대 기준 아님. 사용자가 조정할 것.",
  "A1_cip_ratio":        { "caution": 0.30, "danger": 0.50 },
  "A2_cip_yoy":          { "caution": 0.50, "danger": 1.00 },
  "B2_capex_ratio":      { "caution": 1.00, "danger": 1.50 },
  "B3_capex_초과연수":    { "caution": 2,    "danger": 3 },
  "C3_net_debt_to_ebitda": { "caution": 3.0, "danger": 5.0 },
  "C4_interest_coverage":  { "caution": 2.0, "danger": 1.0, "direction": "below" },
  "C5_debt_growth":      { "caution": 0.30, "danger": 0.70 },
  "D1_dilution_ratio":   { "caution": 0.05, "danger": 0.10 },
  "D3_non_growth_ratio": { "caution": 0.30, "danger": 0.50 }
}
```

### 5.2 판정 규칙

- 각 지표: 정상 / 주의(caution 이상) / 위험(danger 이상) / 판정불가(null)
- `direction: "below"` 지표(C4)는 값이 기준 **이하**일 때 발동
- **종합 등급을 A/B/C/D 단일 등급으로 뭉개지 않는다.** 지표군별 플래그를 개별 표시한다 (단일 등급화는 정보 손실 + 자의적 가중치 개입이므로 금지)
- 판정불가 지표가 있으면 "판정불가 N건"을 명시적으로 표시한다. 숨기지 않는다

## 6. 출력 스키마 (API 응답)

```json
{
  "stock_code": "247540",
  "corp_name": "에코프로비엠",
  "fs_basis": "CFS",
  "fiscal_years": ["2023", "2024", "2025"],
  "latest_quarter": "2026Q2",
  "flags": {
    "A_감가상각절벽": { "level": "위험", "metrics": { "cip_ratio": 0.68, "cip_yoy": null } },
    "B_이익현금괴리": { "level": "주의", "metrics": { "...": "..." } },
    "C_차입리스크":   { "level": "...", "metrics": { "...": "..." }, "included_accounts": ["단기차입금", "..."] },
    "D_희석리스크":   { "level": "...", "metrics": { "...": "..." }, "disclosure_date": "2026-06-30" }
  },
  "unavailable": [ { "metric": "A2", "reason": "전기 건설중인자산 데이터 없음" } ],
  "data_source": "DART fnlttSinglAcntAll (조회일: 2026-08-09)",
  "disclaimer": "공시 데이터 기반 정량 계산. 투자 판단·추천 아님."
}
```

※ 위 수치 예시(0.68 등)는 스키마 형태 예시일 뿐이다. 실제 값은 반드시 API에서 계산한다.

## 7. 구현 단계 (순서 준수)

1. **[검증]** DART 4개 엔드포인트 실호출 → 응답 JSON을 `./docs/dart_samples/`에 저장 → 실제 계정과목명 목록 작성
2. **[모듈]** `backend/services/dart_financial.py`: API 클라이언트 + 캐싱 (동일 종목·동일 보고서 재호출 방지, SQLite 캐시 테이블)
3. **[모듈]** `backend/services/risk_flags.py`: 4장 계산식 구현. 계산 함수는 순수 함수로 작성 (입력: 재무데이터 dict, 출력: 지표 dict) → 단위 테스트 가능하게
4. **[설정]** `backend/config/risk_thresholds.json` 생성
5. **[API]** `GET /api/risk-flags/{stock_code}` 엔드포인트 추가
6. **[브리프]** 모닝브리프 생성 로직에 관심종목 리스크 플래그 섹션 추가 (플래그 발동 종목만 표시, 전 종목 나열 금지)
7. **[테스트]** 8장 검증 프로토콜 수행

## 8. 검증 프로토콜 (완료 조건)

1. **에코프로비엠(247540)으로 전체 파이프라인 실행**하고 결과 JSON을 출력한다
2. 출력된 수치를 DART 원문 공시(사업보고서 재무제표)와 사용자가 직접 대조할 수 있도록, 각 지표에 사용된 **원천 계정과목명과 원본 값**을 로그로 남긴다
3. 계정과목 누락 종목 1개 이상(예: 무차입 기업)으로 `null` 처리 경로를 테스트한다
4. 유상증자 공시가 없는 종목으로 D지표군 부재 경로를 테스트한다
5. 임계값 파일 수정 → 재시작 없이(또는 재시작 후) 판정 변경 확인
6. **모든 검증 결과는 실제 실행 출력 첨부.** "됐을 것이다" 식 보고 금지

## 9. 금지사항 (재확인)

- 재무 수치 추정·보간·하드코딩 금지
- DART 외 소스로 재무 수치 취득 금지 (Google Finance 절대 금지)
- 단일 종합등급 생성 금지, 정성 평가 문구 생성 금지
- 자본화 차입원가 주석 파싱은 이번 범위 제외 (시도하지 말 것 — 추후 별도 지시서)
- 검증 없이 지시서의 필드명을 그대로 코드에 사용 금지
